# Изменения

## v5.3.0 — установщик и готовность к передаче другим пользователям
- Установщик MeetingHubSetup.exe: без прав администратора, в %LOCALAPPDATA%\Programs\Meeting Hub,
  ярлыки в меню «Пуск» (и проверка звука), обновление поверх, удаление без потери данных.
- Данные пользователя (записи, шаблоны, журнал, настройки) — в %LOCALAPPDATA%\Meeting Hub.
  Данные старой версии, лежащие рядом с exe, переносятся автоматически; папку старой ZIP-версии
  мастер находит в «Загрузках» и на рабочем столе и переносит по кнопке (исходник не меняется).
- Мастер настройки при первом запуске: проверка записи и инструкция под причину —
  Kaspersky, запрет микрофона в Windows (с кнопкой открытия настроек), нет устройства,
  другой антивирус, не пишется только звук компьютера.
- Согласие на запись: перед первой записью — предупреждение о необходимости уведомлять участников.
- «Отчёт для поддержки…»: ZIP с журналом, проверкой звука и сведениями о системе,
  без записей, расшифровок и заголовков окон.
- Подпись кода в сборке: включается автоматически, когда в GitHub появятся секреты
  CODESIGN_PFX_BASE64 и CODESIGN_PFX_PASSWORD.
- Портативная ZIP-версия сохраняет данные рядом с программой (portable.txt).
- CI: тихая установка, проверка звука и запись из установленной программы, перенос старых данных,
  обновление поверх и удаление с сохранением данных.

## v5.2.2 — причина найдена: Kaspersky Endpoint Security
- Отчёт пользователя: в процесс программы встроен Kaspersky Endpoint Security 12.12 (com_antivirus.dll);
  доступ к микрофону в Windows разрешён, но не открывается ни одно устройство — ни микрофоны, ни loopback,
  ни одним способом (WASAPI, MME, DirectSound). Это блокировка аудиопотока защитной программой.
- Программа распознаёт это и прямо пишет, что запись блокирует Kaspersky и что сделать
  (проверка записи, журнал решений, отчёт о звуке). Инструкция — в README.txt.

## v5.2.1 — диагностика блокировки звука
- MeetingHub.exe на Python 3.12 у пользователя даёт те же ошибки, что и Python 3.14: значит, дело не в Python,
  а в чём-то на компьютере, что не пускает программу к звуковым устройствам (Chrome при этом работает).
- Подробная проверка звука теперь показывает запущенные антивирусы и DLP (Kaspersky, Dr.Web, ESET,
  InfoWatch, SearchInform и др.) и сторонние библиотеки, загруженные в процесс программы.

## v5.2.0 — готовая программа MeetingHub.exe
- Третий отчёт пользователя: на его компьютере в Python 3.14 не открывается ни одно звуковое устройство
  ни через soundcard, ни через PortAudio (WASAPI, MME, DirectSound), хотя на виртуальной звуковой карте
  в GitHub Actions всё работает. Запись из 1.2.0, собранной на Python 3.12 в exe, на этом компьютере работала.
- Программа теперь собирается в MeetingHub.exe на Python 3.12 (GitHub Actions, PyInstaller):
  не зависит от установленного Python и пакетов. Данные хранятся рядом с MeetingHub.exe.
- Сборка проверяется автоматически на виртуальной звуковой карте: подробная проверка звука,
  запись 4 секунд со звуком компьютера, запуск окна и перенос данных обучения v4.9.
- MeetingHub.exe --audio-check — отчёт о звуке без окна; подробная проверка теперь перебирает все
  устройства записи и показывает настройки доступа к микрофону в Windows.

## v5.1.4 — второй движок записи (PortAudio)
- По второму отчёту пользователя: на его Windows 10 любой вызов IAudioClient::Initialize через пакет
  soundcard (даже в родном формате) возвращает «invalid argument». Причина внутри связки soundcard/cffi
  на этом компьютере, а не в формате.
- Основной движок записи теперь PyAudioWPatch (PortAudio, код на C): микрофон через WASAPI, при отказе —
  MME или DirectSound; звук компьютера — WASAPI loopback. soundcard остаётся запасным.
- Чтение в режиме обратного вызова: тишина в loopback не подвешивает запись.
- Подробная проверка звука показывает раздел PortAudio со списком устройств.

## v5.1.3 — запись в родном формате устройства
- Отчёт пользователя (Windows 10 19045, USB PnP Audio Device): Windows отвергала все форматы
  с автоконвертацией («invalid argument» в IAudioClient::Initialize). Теперь устройство открывается
  в его собственном формате (GetMixFormat без изменений) — этот формат WASAPI принимает всегда;
  каналы сводятся и частота приводится к 16 кГц в программе. Старые варианты остаются запасными.
- Подробная проверка звука показывает результат и для родного формата.

## v5.1.2 — запись: подбор формата и подробная диагностика
- У пользователя Windows отвечала «invalid argument» при открытии обоих устройств. Теперь программа
  пробует несколько форматов (48 / 44,1 / 16 / 96 кГц, моно / стерео, разные размеры буфера)
  и берёт первый, который принимает устройство; звук приводится к 16 кГц.
- «Проверить запись» показывает, какой формат подошёл.
- «Подробная проверка звука…» и audio_check.bat: отчёт meeting_hub_audio_report.txt с точным местом ошибки.
- CI: запись проверяется на виртуальной звуковой карте (VB-Audio) на Python 3.12 и 3.14.

## v5.1.1 — исправление записи
- На компьютере пользователя оба источника записи выдавали «ошибка». Изменения:
  каждый поток записи сам инициализирует COM; захват идёт на родной частоте устройства 48 кГц
  (как в 1.2.0) с понижением до 16 кГц.

- Кнопка «Проверить запись (5 с)» на вкладке «Записи»: устройство, уровень и точная ошибка по каждому источнику.

- `setup_ollama.bat` переименован в `setup.bat` и ставит пакеты записи (numpy, soundcard).

## v5.0 — упрощённое и надёжное обнаружение встреч

### Новая модель обнаружения
- Встреча = окно встречи открыто **и** это приложение держит микрофон → отсчёт 5 с с отменой.
- Выключенный микрофон и тишина встречу не завершают.
- Конец: окно закрыто и микрофон свободен 10 с → вопрос «Встреча закончилась?», завершение через 30 с.
- Браузер с микрофоном в незнакомом окне или окно комнаты без микрофона → только вопрос пользователю.
- Явный конечный автомат (`meeting_detector.py`) — единственный источник истины о состоянии встречи.
- Один цикл опроса в главном потоке вместо нескольких потоков-наблюдателей.

### Исправленные дефекты v4.9
- Звук уведомлений Slack, Discord, Viber и Teams мгновенно включал встречу (ложный старт при запуске).
- Встречу нельзя было завершить автоматически, пока открыт любой браузер.
- Окно-вопрос открывалось за окном конференции и было не видно; теперь окно поверх всех окон.
- Закрытие окна-вопроса крестиком навсегда включало для Chrome правило «Никогда».
- Выключение микрофона в Google Meet дольше 30 с завершало встречу.
- Правило `chrome.exe: always` запускало встречу при любом обращении Chrome к микрофону.
- Правила хранились в двух местах и перезаписывали друг друга.
- Включение/выключение галочки запускало дополнительные параллельные циклы опроса.
- Отложенный анализ после встречи не перезапускался.
- Программа постоянно держала микрофон открытым для измерения уровня звука.
- Сломанные концы строк в `.bat`-файлах.

### Обучение

- Журнал решений с объяснением причины, инициатором и версией алгоритма.
- Миграция данных v4.9 с резервной копией; история хранится без изменений в `legacy_v49`.
